# Handoff notes

## Resumption content

Give the next worker the information for the next authorized action. Link the canonical task, applicable revision and saved sources or outputs. State the unresolved decision or obstacle and the execution context for resumption. Report completed operations as completed and unresolved or interrupted operations as unresolved or interrupted.

Point to the one current checkpoint, including applicable holds, valid dependencies and the next authorized action; do not create a competing status record. Carry the bounded outcome, input revisions, acceptance evidence and output ownership forward. Preserve the current conclusion, supporting evidence, changed paths, deviations and unresolved questions. Separate content dependencies from record locators so a progress update alone does not invalidate scientific work.

Before resuming, reconcile the assignment with actual worker/session identity and running work, check saved evidence for changes and prevent an accidental duplicate of the same substantive task. Reuse unchanged valid work and reopen only affected dependencies. Unknown runtime capabilities remain unknown, and a handoff does not lift a hold or expand authority. Use the [team execution contract](../../econ-workflow/references/team-execution.md) for concurrent or resumable work without repeating task intake or adding a new coordinator.

## Artifact boundary

Keep the handoff and detailed history in operational records, separate from research deliverables. Exclude project plans, progress, stages, decision or adoption status and future user decisions from research prose, explanations, annotations and paraphrases. Report a request that requires these details inside a research deliverable as a conflict before drafting.

## Storage and authority

Carry private asset locators through approved storage. Preserve the user's edit permissions and remote-operation boundaries.
