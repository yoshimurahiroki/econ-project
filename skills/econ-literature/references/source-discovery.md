# Source discovery and evidence

The source connector saves raw responses, retrieval URLs, timestamps and SHA-256 hashes in the requested directory. Its `source_record.json` owns the returned source evidence. Saved raw-response, CSV, corpus-original, extracted-page and source-provenance paths are relative to that record. The existing readers resolve them at the record's location before reuse, metadata refresh or embedding in another record; existing absolute references remain accepted. Publishing a completed generation preserves these references. Select an original passage before adopting an economic claim. A search rank indicates lexical relevance to a query; the researcher supplies and judges mechanisms, estimands, identification, measurements and populations.

`research_sources.py search-paged --query 'terms' --query 'other terms' --per-page 20 --pages 2 --output DIR` queries Crossref using bounded offsets. One to 20 queries, one to 100 results per page and one to 10 pages are accepted. The record retains every query, page, response hash, total, retrieval status, completeness flag, and each work's query origins and rank. DOI identity is case-normalized; a record without a DOI or stable ID needs the same normalized title, author list and year for query deduplication. Remaining records stay distinct. Crossref's declared `link` and `relation` metadata remain attached to the work; acquiring or executing linked material requires a separate authorized operation. Optional `--window R0 --as-of YYYY-MM-DD` supplies execution-relative publication-date filters; `--venue TITLE` supplies Crossref's `query.container-title`. The saved record retains the actual date and filters.

`research_sources.py citations --doi DOI --per-page 20 --pages 2 --output DIR` resolves the DOI in OpenAlex. It returns every referenced work ID in the root response, resolves a bounded prefix of those IDs in batches, and retrieves bounded pages of works that cite the root. Resolved metadata and each response retain their origin; unresolved references remain in the backward list with a null resolution. The result records an error and partial status for a failed direction or page. Forward records are checked against their returned reference lists. The command follows public metadata and makes no action on linked documents or external accounts.

`research_sources.py corpus --spec SPEC.json --output DIR` analyzes local sources. The spec has `query`, `documents`, `limit` and optional `selection`. A document requires `id`, `path` and `format` (`text`, `html`, `pdf`); metadata, stable `paper_id`, source `version`, propositions, relations and uses are optional. DOI normalization supplies a paper identity when none was adopted; a document ID remains valid without a DOI. A paper can retain several explicitly named editions. Metadata is bibliographic evidence, not a replacement for source content.

Text/HTML are UTF-8; PDF uses the installed `pdftotext`. Every run hashes current raw bytes. Each extracted page retains a source ID, content hash and verified text-file reference. Locations use one-based pages and zero-based Unicode `[start,end)` offsets in extracted text; original raw hashes identify the acquired PDF/HTML/text. `--reuse PRIOR_SOURCE_RECORD.json` reuses verified page files for the same format, raw hash and extractor version without copying their bodies. Retain referenced page files with the source record. New or changed bytes are extracted; unsupported drift in retained annotations is rejected.

The original five-facet `propositions` mapping remains accepted. A rich list instead gives each proposition its own stable `id`, `kind` (`claim`, `model`, `identification`, `result`, `interpretation`, `adoption`), `claim`, `attribution: {actor,role}` and nonempty `evidence: [{page,start,end}]`. Roles distinguish author, researcher and decision owner. Optional `facets` include the original mechanism, estimand, identification, measurement and population plus question, contribution, data, estimator, inference, counterfactual and welfare. `facet_evidence` selects the zero-based evidence index for a facet when its support is on another page. Optional `content` preserves the adopted variables, equations, restrictions, estimator or numerical result as a JSON object; `location` names a section, equation, table or figure. Record actual source content and its needed conditions, without forcing an empirical-results form on a theoretical paper. Optional `knowledge_ids` connect the local research question to the existing economics library. An adopted `decision` also requires its actual decision authority.

Typed paper/proposition relations use `kind`, `target: {document_id, proposition_id?}`, `basis`, original `evidence` and optional `conditions`. Kinds are `supports`, `contradicts`, `extends`, `replicates`, `shares_data`, `shares_experiment`, `reuses_result`, `measurement_diff`, `population_diff`, `identification_diff`, `method_critique`, `version_of`. Targets must exist in the same corpus. These are researcher assertions for source comparison, not automatic support or independent replication. Keep studies sharing data, experiments or inherited results distinguishable when weighing evidence. Original `author_code`/`replication` URL relations remain compatible metadata and are not executed by collection.

Passage, proposition and document ranking use BM25 with `k1=1.2`, `b=0.75`, NFKC-normalized case-folded Unicode tokens and recorded document frequencies/mean lengths. Normalization applies to both queries and ranking text; original source bytes, page text and evidence offsets stay unchanged. Paragraphs are split at 1,200 codepoints. Ranking indicates lexical relevance, not truth or novelty. `selection` filters document/proposition IDs, kinds, facets, knowledge IDs or relation kinds before delivering the limited `ranked_propositions`; qualified `document:proposition` IDs disambiguate local IDs. Full canonical annotations remain in the same source record. Downstream design inputs and source uses contain only the delivered selection; the original complete five-facet paper row remains compatible with existing callers.

`research_sources.py corpus --record PRIOR --query TERMS --select '{"kinds":["identification"]}' --limit N --output DIR` searches the saved knowledge without reauthoring propositions. Repeat `--metadata WORK_RECORD.json` to merge DOI-matched output from the existing `work` connector; unmatched metadata is rejected. Unchanged source/version preserves propositions, relations and uses through metadata refresh. The result retains the metadata source hash, raw/page hashes, stable proposition IDs and proposition content hashes. Do not overwrite research interpretations with an external title or abstract update.

Add `--bibliography LIBRARY.json` to either corpus entry to import a local CSL-JSON array, including Zotero CSL exports. The export's path, SHA-256 and original entry remain in metadata. A DOI or citation-key match also requires the same declared edition; ambiguous matches fail. Unmatched entries remain searchable documents with `body_status: missing`, no original hash, pages, propositions or source-use evidence. `ranked_documents` retains every document, including excluded and missing-body entries; rankings do not adopt or remove literature. A local Markdown note uses the existing `format: text` input. Provide the actual original before recording a source passage or using it as evidence.

An optional document `research_selection` contains `status` (`adopted`, `excluded` or `pending`), `reason`, `actor` and `authority`. Adoption requires actual authority; refresh preserves the existing judgment. Explicit `reading_observations` contain `kind` (`ai_inspected` or `human_asserted`), `reader`, `basis` and a nonempty `evidence` list of exact `{page,start,end}` ranges. Human assertions require the researcher's supplied identity and basis. The record binds each observation to the actual original hash, edition, page, text hash and exact extracted quote. Extraction alone is not an assertion of reading. An unchanged original preserves observations; a changed original retains prior observations as `current: false` until new observations are supplied for that edition. These observations do not certify interpretation or source agreement.

`corpus: {path, sha256, proposition_ids, as_of?}` is the shared readonly input for design and evidence review. Optional `as_of` supplies the current task date for shared literature selection. The existing loader verifies record, original source, page, exact quote and proposition hashes and returns selected knowledge, `design_sources` and `design_propositions`; the identifying dimension retains its `identifying_variation` name. It does not adopt a scientific conclusion. The design/review/writing owner reads the source argument and judges its applicability.

## Select a field and retain its ranking

Use [search priority](search-priority.md) for the common scientific selection procedure. `research_sources.py search-plan --field econometrics --field labor --as-of YYYY-MM-DD --output DIR` returns only those fields, their E0/C0 groups, aliases, working-paper series and computed R0–R3 windows. `--theme policing` selects the corresponding crime theme. Omit fields to obtain the field-name catalog. The single [journal policy](journal-priority.json) is machine input; a field lookup supplies its relevant slice. The execution date defaults to the runtime calendar date. Pass the current task date explicitly when its timezone determines the calendar boundary. Every ranking stores that date and the policy hash.

The policy's `leading_journals` lists the concrete tier boundary for each field: the Economists Japan leading-venue selections appearing in that field and its first listed journal. The crime field includes C1 and Criminology. All original within-field orders remain in `journals` or the C0/C1/C2 groups. Selection orders relevance status, venue tier, the researcher's within-tier match priority, R0–R3 and selection year, crime group, theme priority and adopted venue rank. Citation counts supply no ranking term. W1 is recent in R0/R1; older W1 and official W2 use the major-field tier. SSRN and arXiv retain their discovery-platform role.

`research_sources.py rank --record SOURCE_RECORD.json --spec PRIORITY.json --as-of YYYY-MM-DD --limit 20 --output DIR` adds `search_priority` to that same record format. `PRIORITY.json` accepts `fields`, optional `theme`, `question`, `direct_only` and `matches`. A `matches` object is keyed by document ID or a discovery work's DOI/ID. Each assessed match supplies `status` (`direct`, `related`, `excluded`), `actor`, `basis`, optional positive integer `priority`, and optional research-question `dimensions`. Direct matches additionally supply `evidence: [{page,start,end}]` in that candidate's corpus body. Every range must be covered by an explicit current reading observation. Bibliographic-only records remain unassessed discovery candidates until original-body evidence is available. `direct_only: true` retains direct matches.

Use the same specification as a corpus spec's `search_priority`, or pass `corpus --priority PRIORITY.json`. Its ranked study order controls the delivered passages, propositions, comparison rows and design inputs while the complete corpus remains saved. `corpus --record` reuses the saved priority specification and recomputes its execution date. The existing `load_corpus_record` also returns the shared `search_priority`; its optional `as_of` uses the task's date. Explicit proposition selections retain their existing meaning and exact source bindings.

Crossref metadata retains actual authors, original author records, container title, publisher, type, volume, issue, page range, and separate `published_online`, `published_print`, `published`, `issued`, `accepted` and `posted` dates at their original precision. A status inferred from those dates is labelled `publication_status_inferred`; later execution recomputes it. A source can supply actual `wp_first_release`, `first_release`, `revised` and `latest_revision` dates. Deposit and index timestamps never supply a manuscript revision. A generic official W2 series supplies `official_wp: {institution_kind,series,official_url,basis}`, with institution kind `central_bank`, `university` or `research_institute`.

The ranked result contains one position per study and retains all `versions`. Shared DOI/stable paper identities, publisher preprint/version relations and source-bound `version_of` relations establish aggregation. `edition_reconciliation` names the formal publication, inspected match edition, latest available manuscript and the exact identity links. Original claims stay bound to their document ID, version and source hash. The latest manuscript uses reported revision, posting or online/publication dates through the execution date. Metadata refresh preserves the preceding publication fields in `publication_history` and reports `changes.publication_changed`; changed original bytes retain the existing explicit annotation and reading rules.

## Read a bounded saved selection

`research_sources.py view --record CORPUS.json --sha256 HASH --limit 5 --as-of YYYY-MM-DD` returns bounded bibliographic metadata, publication state, page/proposition counts and the top shared study selection. Repeat `--document ID` to select specific documents. Page bodies stay in the original record.

`research_sources.py passage --record CORPUS.json --sha256 HASH --document ID --page 3 --start 120 --end 950` returns that exact range with the original edition, original/page/quote hashes and source identity. Offsets remain zero-based Unicode positions; pages remain one-based. Omit offsets for the entire selected page. The default response bound is 12,000 characters; select smaller ranges or supply `--max-chars` up to 100,000. The reader verifies the adopted record, current original bytes and extracted page. It performs no write and creates no reading observation. After inspecting the returned text, record the actual reading through the existing `reading_observations` input. The original full corpus and proposition-reader interfaces remain supported.

## Discover current Doleac sources

`research_sources.py doleac --file-metadata DRIVE_RESPONSE.json --as-of YYYY-MM-DD --theme policing --output DIR` reads current public spreadsheet tab metadata and the Resources page, then acquires Accepted, the latest existing annual tab through the execution year, its preceding two existing annual tabs and Overview. Repeat `--older-year YEAR` for additional existing years. Actual sheet IDs come from the returned tab inventory, including valid ID zero. The Resources page supplies its currently published crime-research and literature-review links.

The command also accepts `--sheet-metadata SHEETS_RESPONSE.json` from the current native Sheets metadata tool or Sheets API. Both metadata arguments accept the actual JSON object or a native connector response's `structuredContent`. Sheets input uses `sheets[].properties.title` and `sheetId`; Drive input uses `id` and `modifiedTime` or `modified_time`. Preserve the original returned files. The command stores their hashes and import provenance in `source_record.json`. Obtain fresh metadata for the current search.

`source_modified_time` is the Drive value. Overview's per-venue `coverage_date`, its actual row and column, and HTTP retrieval times remain separate fields. A missing Drive modification field produces an explicit partial result. The record retains the selected source rows, their exact public response hashes, reported authors and publication status, current Resources links, execution-relative supplemental plan and years beyond the latest existing tab. Acquire research after each venue's reported coverage through the official journal and WP routes in the shared search plan.

Optional `uses` retain `decision_id`, `purpose`, `page`, `start` and `end` beside the source. A new record's `changes` identifies added/changed/removed propositions, edition/relation changes and overlapping `uses_to_reassess`. Bibliography-only updates preserve semantic versions. A proposition change directs reassessment to its consumed uses; a source-edition or relation change can require the paper's wider uses to be reconsidered. A changed original with an existing research-selection judgment requires its owner's explicit updated selection. The owner updates the affected adopted specification or proposition output through existing task state and its consumed versions, preserving valid calculations and rebuilding only affected descendants. Neither the collector nor a lexical score changes authority or invalidates unrelated results. Keep local PDFs, bibliography records and research notes in the research project's authorized storage, outside the public generic plugin.
