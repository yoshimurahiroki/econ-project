# Source discovery and evidence

The source connector saves raw responses, retrieval URLs, timestamps and SHA-256 hashes in the requested directory. Its `source_record.json` owns the returned source evidence. Select an original passage before adopting an economic claim. A search rank indicates lexical relevance to a query; the researcher supplies and judges mechanisms, estimands, identification, measurements and populations.

`research_sources.py search-paged --query 'terms' --query 'other terms' --per-page 20 --pages 2 --output DIR` queries Crossref using bounded offsets. One to 20 queries, one to 100 results per page and one to 10 pages are accepted. The record retains every query, page, response hash, total, retrieval status, completeness flag, and each work's query origins and rank. DOI identity is case-normalized; for works without a DOI, normalized title and year define identity. Distinct identifiers and unknown identities remain distinct. Crossref's declared `link` and `relation` metadata remain attached to the work; acquiring or executing linked material requires a separate authorized operation.

`research_sources.py citations --doi DOI --per-page 20 --pages 2 --output DIR` resolves the DOI in OpenAlex. It returns every referenced work ID in the root response, resolves a bounded prefix of those IDs in batches, and retrieves bounded pages of works that cite the root. Resolved metadata and each response retain their origin; unresolved references remain in the backward list with a null resolution. The result records an error and partial status for a failed direction or page. Forward records are checked against their returned reference lists. The command follows public metadata and makes no action on linked documents or external accounts.

`research_sources.py corpus --spec SPEC.json --output DIR` analyzes local sources. The spec has `query`, `documents`, `limit` and optional `selection`. A document requires `id`, `path` and `format` (`text`, `html`, `pdf`); metadata, stable `paper_id`, source `version`, propositions, relations and uses are optional. DOI normalization supplies a paper identity when none was adopted; a document ID remains valid without a DOI. A paper can retain several explicitly named editions. Metadata is bibliographic evidence, not a replacement for source content.

Text/HTML are UTF-8; PDF uses the installed `pdftotext`. Every run hashes current raw bytes. Each extracted page retains a source ID, content hash and verified text-file reference. Locations use one-based pages and zero-based Unicode `[start,end)` offsets in extracted text; original raw hashes identify the acquired PDF/HTML/text. `--reuse PRIOR_SOURCE_RECORD.json` reuses verified page files for the same format, raw hash and extractor version without copying their bodies. Retain referenced page files with the source record. New or changed bytes are extracted; unsupported drift in retained annotations is rejected.

The original five-facet `propositions` mapping remains accepted. A rich list instead gives each proposition its own stable `id`, `kind` (`claim`, `model`, `identification`, `result`, `interpretation`, `adoption`), `claim`, `attribution: {actor,role}` and nonempty `evidence: [{page,start,end}]`. Roles distinguish author, researcher and decision owner. Optional `facets` include the original mechanism, estimand, identification, measurement and population plus question, contribution, data, estimator, inference, counterfactual and welfare. `facet_evidence` selects the zero-based evidence index for a facet when its support is on another page. Optional `content` preserves the adopted variables, equations, restrictions, estimator or numerical result as a JSON object; `location` names a section, equation, table or figure. Record actual source content and its needed conditions, without forcing an empirical-results form on a theoretical paper. Optional `knowledge_ids` connect the local research question to the existing economics library. An adopted `decision` also requires its actual decision authority.

Typed paper/proposition relations use `kind`, `target: {document_id, proposition_id?}`, `basis`, original `evidence` and optional `conditions`. Kinds are `supports`, `contradicts`, `extends`, `replicates`, `shares_data`, `shares_experiment`, `reuses_result`, `measurement_diff`, `population_diff`, `identification_diff`, `method_critique`, `version_of`. Targets must exist in the same corpus. These are researcher assertions for source comparison, not automatic support or independent replication. Keep studies sharing data, experiments or inherited results distinguishable when weighing evidence. Original `author_code`/`replication` URL relations remain compatible metadata and are not executed by collection.

Passage and proposition ranking use BM25 with `k1=1.2`, `b=0.75`, normalized Unicode tokens and recorded document frequencies/mean lengths. Paragraphs are split at 1,200 codepoints. Ranking indicates lexical relevance, not truth or novelty. `selection` filters document/proposition IDs, kinds, facets, knowledge IDs or relation kinds before delivering the limited `ranked_propositions`; qualified `document:proposition` IDs disambiguate local IDs. Full canonical annotations remain in the same source record. Downstream design inputs and source uses contain only the delivered selection; the original complete five-facet paper row remains compatible with existing callers.

`research_sources.py corpus --record PRIOR --query TERMS --select '{"kinds":["identification"]}' --limit N --output DIR` searches the saved knowledge without reauthoring propositions. Repeat `--metadata WORK_RECORD.json` to merge DOI-matched output from the existing `work` connector; unmatched metadata is rejected. Unchanged source/version preserves propositions, relations and uses through metadata refresh. The result retains the metadata source hash, raw/page hashes, stable proposition IDs and proposition content hashes. Do not overwrite research interpretations with an external title or abstract update.

Add `--bibliography LIBRARY.json` to either corpus entry to import a local CSL-JSON array, including Zotero CSL exports. The export's path, SHA-256 and original entry remain in metadata. A DOI or citation-key match also requires the same declared edition; ambiguous matches fail. Unmatched entries remain searchable documents with `body_status: missing`, no original hash, pages, propositions or source-use evidence. `ranked_documents` retains every document, including excluded and missing-body entries; rankings do not adopt or remove literature. A local Markdown note uses the existing `format: text` input. Provide the actual original before recording a source passage or using it as evidence.

An optional document `research_selection` contains `status` (`adopted`, `excluded` or `pending`), `reason`, `actor` and `authority`. Adoption requires actual authority; refresh preserves the existing judgment. Explicit `reading_observations` contain `kind` (`ai_inspected` or `human_asserted`), `reader`, `basis` and a nonempty `evidence` list of exact `{page,start,end}` ranges. Human assertions require the researcher's supplied identity and basis. The record binds each observation to the actual original hash, edition, page, text hash and exact extracted quote. Extraction alone is not an assertion of reading. An unchanged original preserves observations; a changed original retains prior observations as `current: false` until new observations are supplied for that edition. These observations do not certify interpretation or source agreement.

`corpus: {path, sha256, proposition_ids}` is the shared readonly input for design and evidence review. The existing loader verifies record, original source, page, exact quote and proposition hashes and returns selected knowledge, `design_sources` and `design_propositions`; the identifying dimension retains its `identifying_variation` name. It does not adopt a scientific conclusion. The design/review/writing owner reads the source argument and judges its applicability.

Optional `uses` retain `decision_id`, `purpose`, `page`, `start` and `end` beside the source. A new record's `changes` identifies added/changed/removed propositions, edition/relation changes and overlapping `uses_to_reassess`. Bibliography-only updates preserve semantic versions. A proposition change directs reassessment to its consumed uses; a source-edition or relation change can require the paper's wider uses to be reconsidered. A changed original with an existing research-selection judgment requires its owner's explicit updated selection. The owner updates the affected adopted specification or proposition output through existing task state and its consumed versions, preserving valid calculations and rebuilding only affected descendants. Neither the collector nor a lexical score changes authority or invalidates unrelated results. Keep local PDFs, bibliography records and research notes in the research project's authorized storage, outside the public generic plugin.
