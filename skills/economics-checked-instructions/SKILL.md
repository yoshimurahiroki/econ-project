# Paragraph and hierarchical argument workflow

Read `get_policy` and `get_guidance` for the adopted operation and its registered rules. Apply the canonical paragraph and argument schemas to `econ-writing:compose`, `econ-writing:revise`, `econ-writing:translate`, `econ-writing:explain`, and `econ-writing:convert`. Use one contract for a single paragraph and separate contracts for every paragraph in a document.

Fix the Global Writing Blueprint, hierarchical argument, source correspondence and version hashes before writing. Separate argument parent/child relationships from paragraph dependencies. Give each paragraph its central proposition, local reader question, required claims, evidence locations, reasoning, order, terminology, scope and completion criteria. Retain the source definitions, quantities, subjects, periods, units and adopted content.

Run the seven stages through the canonical workflow: global argument design, paragraph specifications, paragraph writing, local checks, section integration, manuscript integration and independent final review. Assign independent paragraphs to actual host workers and follow dependency order for dependent paragraphs. Record real worker launches and original returns. Use the registered sequential contract route when the host provides no worker launcher, and record that execution mode accurately.

Persist paragraph contracts, artifacts, sources, rule hashes, assignments and checks through `specified → source-ready → assigned → drafted → locally-reviewed → integrated → globally-reviewed`. On text, specification, source, rule or dependency changes, invalidate the affected checks and dependent paragraphs through the canonical state functions. Restore valid completed work, fixed request and applicable instructions on resumption. Retain interrupted assignments until the host provides their original completed return or a recorded terminal failure. Source consumers include required evidence, writing references and blueprint references; a changed source catalog expires the argument and integration reviews.

Check parent/child support, sibling grouping and order, reader-question coverage, deductive and inductive links, quantitative evidence, missing claims, duplication and scope. Reconstruct the argument from the integrated manuscript and compare it with the blueprint. Recheck every changed paragraph and its affected dependencies. Bind each mandatory proposition to its argument-node ID, including the single node of an atomic paragraph. Require each semantic check to cover its applicable nodes, preserve numeric signs in source matches, and match sibling positions to their declared order.

The native checker validates schema, candidate text correspondence, evidence and required states. Repair the reported native check IDs, update the packet and candidate together, and obtain reviews for the resulting submission hash.

Copy the native `paragraph_packet_sha256` into each writing review's scope, original Quality A / Quality B / Compliance return, and coordinator-match record. Keep it equal to the registered assignment scope. Replacing the packet invalidates those reviews even when the final candidate text is unchanged.

Keep the native reports envelope at exactly `schema_version`, `reports`, and `unresolved_flags`. Send host assignment, review and coordinator-match control records through the existing control-record sequence. Keep paragraph state out of that envelope. Internal views stay in private validation state and are excluded from released artifacts.
