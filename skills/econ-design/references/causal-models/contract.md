## Specification and result

Use `python skills/econ-data/scripts/research_causal.py run SPEC.json --output RESULT.json`. The shared specification binds `method`, canonical `data` or hashed `data_record`, unique nonempty `id`, `outcome`, `regressors`, `endogenous`, `instruments`, population/period/unit, estimand, identification, assignment, inference and method-specific `options`. Relative paths resolve against the specification. CSV, Parquet and Arrow IPC share the existing projected reader; preserve textual IDs and the selected method's observation rule, including unobserved outcomes for selection models.

Use the selected method's body and selector-produced execution specification for its columns, inference type and options. The common contract does not enumerate every method's parameters. Python matrix estimators require numeric analysis columns; native R functions own factor encoding. Preserve the adopted intercept/fixed-effect/differencing rule and coefficient scale. Execution validates the actual input/interface before fitting.

Results retain engine versions, named estimates/covariance/inference, fitted/excluded IDs, row/sample counts, diagnostics, definitions, input hashes and semantic `statistics` with units. Method contracts own their native quantities and row mapping; shared atomic publication owns saving. The existing `research.py estimate` retains its persisted OLS/2SLS/PLR/two-period-DID formats; new DoubleML selections use the causal runner.
