## Bayesian project-model execution

Use for Bayesian project models (PyMC, CausalPy, Stan engines) and Julia fixed effects and IV.

`bayesian_model` uses the same causal `run` command with `inference={"type":"posterior","credible_level":0.95}`. Required options are `engine`, `model_file`, `builder`, `posterior_output`, `var_names` and `sampling`. The selector binds the package environment to `engine`:

| Engine | Official package versions | Native posterior |
| --- | --- | --- |
| `pymc` | PyMC 6.4.0, ArviZ 1.3.0, arviz-stats 1.3.3 | `xarray.DataTree` |
| `causalpy` | CausalPy 0.9.0, PyMC 5.28.5, ArviZ 0.23.4, pymc-extras 0.10.0, PyTensor 2.38.3, PreliZ 0.25.0 | `arviz.InferenceData` |

Both environments use the selected NumPy/pandas inputs, SciPy 1.18.1, xarray 2026.9.0, h5netcdf 1.8.2 and h5py 3.16.0. The CausalPy closure also pins better-optimize 0.5.1, arviz-stats 1.3.3 and scikit-learn 1.7.2. CausalPy 0.9.0's official `fit` calls `InferenceData.extend`; its package requires `pymc<6`, `arviz<1.0` and `pytensor<3`. The runner enforces these API families before executing the project builder. Bind each selected interpreter and its package closure to the existing research stage.

The existing Python `model_file` defines `builder(data, specification)`. For `engine="pymc"`, it returns the adopted `pm.Model` with its likelihood, priors, coordinates and economic quantities. For `engine="causalpy"`, it returns a fitted official `PyMCModel` or a Bayesian `BaseExperiment`. A model such as `causalpy.pymc_models.LinearRegression` executes its official `fit(X, y, coords)`; an experiment constructor executes its own fit. Bind `specification["options"]["sampling"]` to the model's `sample_kwargs`. The wrapper reads the model's native `idata`. The builder owns transformations, priors, named economic quantities and observation mapping. `pm.compute_deterministics` can calculate requested parameter transformations from the existing posterior. Input IDs and the native observed-data coordinates remain attached.

`sampling` declares integer `draws`, `tune`, `chains` and `random_seed`, with at least two chains and four retained draws per chain. Other arguments go to the selected official `pm.sample`; the project chooses its actual inference budget. Optional `prior_predictive` and `posterior_predictive` objects execute the corresponding official PyMC function with the declared arguments. PyMC 5.28.5 and 6.4.0 prior prediction use `draws`. The CausalPy fit retains its native prior and posterior predictive groups; explicit predictive options replace the corresponding groups with their requested draws. These updates preserve the fitted `observed_data` and `constant_data`. The result records actual call order, effective seeds and groups. `model_dependencies` lists model helpers or inputs whose content hashes belong to the saved calculation.

ArviZ receives the selected `var_names`, `round_to="none"` and `kind="all"`. ArviZ 1 uses `ci_prob=credible_level` and `ci_kind="hdi"`; ArviZ 0.23.4 uses `hdi_prob=credible_level`. The result saves native posterior means, posterior SDs, HDI endpoints, bulk/tail ESS, rank R-hat, Monte Carlo errors and sampler divergence counts. Optional `diagnostics` declares `r_hat_max`, `ess_bulk_min`, `ess_tail_min` and `divergences_max`; each saved criterion contains its actual value, threshold and outcome. A threshold applies to every selected posterior quantity; an undefined diagnostic fails that adopted criterion. A failed criterion retains the complete rejected posterior at the unique sibling path returned in the error and preserves the preceding accepted `posterior_output`. `definitions.parameter_units` maps exact posterior-summary term labels to their units; other terms use `spec.unit`.

`observation_coord` names the coordinate that indexes the native `observed_data` outcome. Its unique values must match canonical input IDs; the common result then retains actual fitted membership and can satisfy a required shared sample. Model-specific aggregation keeps its native observation map.

`posterior_output` is a `.nc` or `.netcdf` path relative to the specification. The native `DataTree.to_netcdf` or `InferenceData.to_netcdf` with `h5netcdf` and `h5py` writes the full posterior, sampler statistics and generated predictive groups to a temporary sibling, followed by atomic replacement. The common JSON identifies the native format and stores its path, SHA-256, group/dimension map, summaries and actual producer/model/dependency versions. Figures and prose consume those saved posterior quantities. Posterior SDs and HDIs retain their Bayesian definitions.

Official APIs: [PyMC sampling](https://www.pymc.io/projects/docs/en/stable/api/generated/pymc.sample.html), [PyMC 5.28.5](https://pypi.org/project/pymc/5.28.5/), [PyMC posterior transformations](https://www.pymc.io/projects/docs/en/stable/api/generated/pymc.compute_deterministics.html), [ArviZ 1 summary](https://arviz-stats.readthedocs.io/en/stable/api/generated/arviz_stats.summary.html), [ArviZ 0.23.4 summary](https://github.com/arviz-devs/arviz/blob/v0.23.4/arviz/stats/stats.py), [InferenceData storage](https://github.com/arviz-devs/arviz/blob/v0.23.4/arviz/data/inference_data.py), [CausalPy 0.9.0 metadata](https://pypi.org/project/causalpy/0.9.0/), [CausalPy model implementation](https://github.com/pymc-labs/CausalPy/blob/v0.9.0/causalpy/pymc_models.py), [pymc-extras 0.10.0](https://pypi.org/project/pymc-extras/0.10.0/), and [DataTree NetCDF](https://docs.xarray.dev/en/stable/generated/xarray.DataTree.to_netcdf.html).

An adopted Stan, NumPyro or Turing model uses the same `design="bayesian_model"` selector with its selected `options.engine` and the [official project-script stage](../../../econ-data/references/implementation-calls.md#official-project-scripts). The [Bayesian implementation selection](../../../econ-data/references/implementation-engines.md#bayesian-project-implementations) owns those native calls and installation conditions. An adopted PyMC model retains this runner's existing interface; a project-specific posterior decision or predictive comparison can consume its saved native posterior through the same stage/result dependencies.

## Julia fixed effects and IV

`fixed_effects_julia` calls official `FixedEffectModels.reg` on the canonical CSV, Parquet or Arrow table through the shared reader. `regressors`, `endogenous` and `instruments` retain the adopted linear/IV formula; `options.fixed_effects` lists the absorbed groups, including an empty list for the unabsorbed model. Select `inference.type="robust"`, `"homoskedastic"` or `"cluster"` with one `cluster` or a `clusters` list. Native `Vcov` supplies the covariance and its residual-degree-of-freedom reference. Weights require `options.weights` and `weights_type="analytic"`.

The entry fixes CPU Float64 and passes `tol`, `maxiter`, `drop_singletons` and `confidence_level` to the native operations. It requires convergence and positive residual degrees of freedom and retains official `esample`, excluded IDs, dropped terms, cluster counts and the Kleibergen–Paap F statistic. The existing `iv_ar_robust` owns effective F and weak-IV-robust confidence sets. Selection of Julia preserves the existing identification and inference contract.

The research stage's Julia companion supplies the executable and complete `probe_argv` prefix to this entry through `ERS_JULIA_ARGV`. The actual fit uses that same prefix, including its `--project` and startup options, with the stage's `JULIA_PROJECT`, `JULIA_DEPOT_PATH` and `JULIA_LOAD_PATH`. Bind Project.toml, Manifest.toml and the package closure in that runtime. An explicit `options.julia` must resolve to the companion's executable. Standalone calls use `options.julia` or `julia` with `--startup-file=no`. The result retains the effective Julia prefix and actual active project.

Optional `native_output` retains the fitted object using Julia Serialization with its runtime version, table hash and fitted IDs. The default embeds that same fit as base64 for compatibility with the existing saved-model convention. Named coefficients, full covariance, p-values, intervals and display rows are exported from this fit. Later use reads the saved object and these quantities without fitting again.
