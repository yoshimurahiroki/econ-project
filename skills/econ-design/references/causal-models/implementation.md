## Select the implementing function

Use to select the implementing function from a design file, including structural model contracts; run `research_causal.py select` and adopt its execution specification.

Run `python skills/econ-data/scripts/research_causal.py select DESIGN.json --output SELECTION.json`. Supply `question`, `estimand`, `identification`, `design`, `outcome_scale`, `data_structure`, `treatment_pattern` and `dependence`; each is a nonempty string. `options` carries the proposed native arguments. The output supplies `method`, `engine`, `entry_point`, determining conditions, the selected method's quantity and the unchanged options. Selection executes no estimation.

An optional `model_contract_id` resolves through the existing knowledge reader and the catalog's `selection_binding`. It carries the full input/output/equation contract, body locators and hashes, actual check/result provenance and knowledge prerequisites into `method_selection`. The existing structural branch checks the requested target, declared economic model and numerical method, then matches its runner command or official function to the contract implementation. A conflicting declared model or target is rejected. Contracts without a selector binding return `implementation_required`, with `theory_only` or `implementation_only` identifying the existing content. For bound growth, market, dynamic and finite numerical models, a matching `adopted_specification` is projected into the selected owner's public run schema; missing fields remain explicit. The adopted object is returned unchanged. The [finite numerical contracts](../numerical-models.md#finite-economic-model-execution) connect correlated equilibrium, Shapley/core allocation, interbank clearing and multitask incentives to `research_numerics.py run`, with the existing function signatures determining required input names. The replacement runner records its actual NFXP, CCP, finite-horizon and scenario components, plus SMM when the adopted options request it.

`MC-aiyagari-stationary` selects the existing macro runner's finite-grid stationary equilibrium, with `numerical.solution_method="policy_iteration_brentq"` and target `equilibrium` or `welfare`. The adopted calibration, baseline/scenario productivity and solver tolerances pass to its exact public specification. `MC-hank-one-asset` selects the official SSJ `Block` operation named by `numerical.operation`: `solve_steady_state`, `solve_jacobian`, `solve_impulse_linear` or `solve_impulse_nonlinear`; these entries target `equilibrium` and return their distinct object contracts. The official `dag()` example performs its public steady-state calibration. A chosen model and saved steady state must carry the adopted grids, parameters and population into each operation. `stochastic_rbc` retains the existing observed-productivity/local-policy runner; `implementation="dolo"` selects official time iteration for that same RBC model. `dolo_yaml` accepts another explicitly declared native model and assigns no RBC contract to it. External Dolo entries target equilibrium solution, retain calibration and save final-policy original residuals alongside the solver's returned diagnostics.

`MC-hark-consumption-saving` selects `research_macro_extended.py run` with `model="consumption_saving"`. `conditions.income_process` or the adopted `income_process` selects `perfect_foresight` or `idiosyncratic_shocks`. The execution specification preserves `consumer_options`, `evaluation`, `calibration_source` and optional `scenario`/`simulation`. The selector records the finite-lifecycle proposal `consumer_options.cycles=1` and, for idiosyncratic shocks, `vFuncBool=true`; the adopted object remains unchanged. `evaluation.mNrm` names the resource grid, with optional periods and population weights. `numerical.operation="simulate"` requires `simulation`; `"counterfactual"` requires `scenario.consumer_options`. The existing runner calls the official consumer's `solve`, evaluates age-specific `cFunc` and `vFunc`, and saves requested histories and scenario contrasts. Targets are individual policy value and welfare at exogenous prices; the existing equilibrium owner performs market clearing.

`MC-qse-open-city` selects `research_macro_extended.py run` with `model="qse_open_city"`, `operation="counterfactual"`, a hash-bound `saved_solution` and `scenario`. Its structural identity is `conditions.economic_object="open_city_commuting"`. The saved closed-city baseline supplies the urban primitives, calibrated parameters and expected utility; population adjusts until scenario expected utility equals that baseline value. The selector retains the common traded good, mixed floor use, fixed floor endowment and external floor owners. It supports equilibrium and welfare targets through `trust_region_least_squares`. `MC-qse-commuting` retains closed-city inversion and counterfactuals with fixed total population.

`adopted_specification` accepts the existing analysis specification as an object and returns that object unchanged. The selector derives its adopted method from `method` or `model`; an explicit `adopted_method` must agree. Supply `population`, `comparison_group`, `observation_unit`, `assignment_unit`, `inference_unit`, `period`, `assignment`, `weights` and `inference` to retain those definitions in `design_contract`. `unit` remains the existing specification's coefficient scale; `observation_unit` names the observed economic unit. Definitions already present in the adopted specification are carried forward, including `options.definitions` and population/weights declared in `target`. DID comparison-group and weight definitions and native weight arguments are also read from its existing options. The economic chain uses these recovered weights and inference units. Changed methods, estimands, identification statements, supplied scientific definitions or options produce `status="design_change"` with the adopted and selected values and their stated estimand relation. The selector does not rewrite or execute the adopted specification.

The design values are `conditional_mean`, `conditional_quantile`, `quantile_effect`, `quantile_did`, `changes_in_changes`, `post_estimation`, `sample_selection`, `survival`, `oaxaca`, `bunching`, `did`, `continuous_did`, `network_interference`, `partial_identification`, `rdd`, `density_at_cutoff`, `rd_power`, `iv` (also `instrumental_variables`), `weak_instrument_inference`, `synthetic_control`, `generalized_synth`, `orthogonal_score`, `heterogeneous_effect`, `policy_learning`, `parallel_trend_sensitivity`, `wild_cluster_inference`, `small_cluster_inference` and `structural`. Conditional means use `outcome_scale="level"` or `"proportional_nonnegative"`. DID uses `treatment_pattern="two_period"`, `"absorbing_staggered"`, `"fixed_dose_common"`, `"fixed_dose_staggered"`, `"multiple_two_period"`, `"reversals"`, `"changing_dose"` or `"treatment_histories"`; two-period data use `data_structure="panel"` or `"repeated_cross_section"`. Orthogonal-score selection takes `score="plr"`, `"did"`, `"irm"`, `"pliv"` or `"iivm"` through this causal runner. The existing `research.py estimate` interface remains available to its previously adopted specifications. Structural selection takes `structural_model` and returns its existing market, dynamic, macro or numerical owner.

The selector accepts each named inference/causal extension as `design`, and returns its exact execution specification and selected package closure. `execution_context` supplies existing `available_languages`, `data_engine`, `memory_budget_bytes`, `working_set_bytes` and observed `performance`. The resulting `execution_plan` preserves scientific definitions and chooses source-side SQL when the declared working set exceeds the memory budget. `implementation="FixedEffectModels.jl"` selects its official linear/IV entry; an automatic performance choice requires the actual data/specification hashes, elapsed seconds and precision. `structural_model="np_demand"` selects the NPDemand Julia project-stage contract for a `structural_parameter` or `elasticity` target.

For these additions, `official_implementation.install_requirements` contains the selected Python packages and `runtime.packages` contains their version checks. Its `dependency_sources` and `runtime.files` retain the owning requirements file without installing that whole family. Bind the actual interpreter in `runtime.probe_argv`; Julia companions bind the adopted Project/Manifest paths and executable. Bayesian selection uses its PyMC-compatible SciPy environment. SQL and typed-table packages are added for the selected data operation and format. Existing whole-family requirement files remain available to their adopted environments.

The same selector accepts `rct`, `rct_design` and `auto` and these structured objects:

| Field | Economic and execution content |
| --- | --- |
| `economic_model` | `actors`, `objectives`, `choices`, `constraints`, `information`, `interactions`, `equilibrium`, `welfare`. Preserve the actual model primitives and equations in their existing specification. |
| `target` | `kind` and the mathematical `expression`, population and weights. Kinds include `ate`, `att`, `itt`, `late`, `cate`, `policy_value`, `linear_projection`, `conditional_mean`, `count_distribution`, `group_time_att`, `event_time_att`, `att_d`, `acrt_d`, `acrt`, `event_time_acrt`, `treatment_vector_effect`, `exposure_contrast`, `identified_set`, `treatment_path_effect`, `dose_response`, `local_effect`, `confidence_set`, `treated_trajectory`, `treated_block_att`, `structural_parameter`, `equilibrium`, `welfare`, `sensitivity`, `conditional_quantile`, `qte`, `qtt`, `counterfactual_distribution`, `marginal_effect`, `average_marginal_effect`, `prediction`, `probability` and `prediction_contrast`. |
| `conditions` | Structured assignment/identification and estimator choices. `assignment_mechanism` selects an `auto` branch from `randomized`, `parallel_trends`, `threshold`, `instrument`, `selection_on_observables`, `conditional_mean`, `donor_panel`, `structural_equilibrium`, `network_randomized`, `partial_identification`. Boolean restrictions use actual booleans. `conditional_distribution="nb2"` chooses the NB2 likelihood. `weak_instruments=true` selects Anderson–Rubin test inversion: the existing F contract for explicitly independent homoskedastic normal errors, or official `ivDiag::AR_test` for robust/clustered inference. `discontinuity="fuzzy"` adds receipt/exclusion/monotonicity conditions. |
| `comparison` | Eligible controls, event window, reference, aggregation population, `interval_type` and `inference_family`. Preserve target-specific contrasts across estimates. |
| `numerical` | `estimation_method` names the algorithm implemented for that model: GMM, NFXP/MPEC, CCP/SMM, EM, entry moment inequalities or its sequential methods, share inversion, maximum likelihood, equilibrium solution or deferred acceptance. The selector returns its actual execution owner and required native options. |

For a marginal quantile target, `quantile_effect` chooses `qte` or `qtt`. Under `auto`, randomized or selection-on-observables assignment with a QTE/QTT target selects `quantile_effect`. A `counterfactual_distribution` target uses the distribution-identified `quantile_did` or `changes_in_changes` route; the selector rejects the `unc_qte` quantile-grid ECDF for that target. A parallel-trends distributional target requires `conditions.distribution_identification="quantile_parallel_trends"` or `"changes_in_changes"`. `conditional_quantile` selects the existing conditional QR with its robust pointwise covariance. `post_estimation` selects `marginaleffects` and requires the exact native `options.function`. The selector binds the adopted response scale, evaluation-weight column, confidence level and cluster formula into the native post-estimation arguments.

For absorbing DID, `conditions.estimator` selects `group_time`, `cohort_interaction`, `imputation`, `two_stage` or `fixes`. Their runner methods are respectively `staggered_did`, `sunab`, `did_imputation`, `did2s` and `fixes_event_study`. For changing treatment paths, `switcher` chooses `did_multiplegt_dyn` and `nonabsdid` chooses `nonabs_did`. `effect_normalization="per_unit_dose"` names the normalized current/lagged dose target; its corresponding native `normalized` option belongs in the execution specification. `counterfactual_model="synthetic_did"` selects `synthdid`; `interactive_fixed_effects` selects `generalized_synth`. A `treated_block_att` uses the common-block SDID contract. These choices preserve the original request and return method changes as proposals.

`method_selection` contains `selected_method`, the estimator's exact `estimand`, structured conditions, required inputs, assumptions, inference, official implementation, determining reason, alternatives and `economic_chain`. Each alternative returns its `estimand`, identifying `conditions`, `data_fit`, `inference`, `target_comparison` and `adopted_specification_changes`. Data fit compares the declared panel/cross-section structure, treatment history, outcome scale and dependence with that candidate's requirements. Its `basis` records that selection uses declared inputs. Target comparison records the candidate's supported mathematical targets. The adopted comparison preserves the existing parameter, identifying statement, population/weights/aggregation and inference beside the candidate's corresponding requirements. Structural alternatives are restricted to algorithms supported by the selected model.

The chain retains the economic decision, target, population/observations, identifying comparison, estimator/weights/numerics and function/options. `forward_options` preserves the supplied or inherited native options. `official_implementation.options` returns the proposed target-consistent options, and `option_changes` records each changed effective setting. For group-time DID, ATT selects `aggregation.type="simple"`, event-time ATT selects `"dynamic"`, and panel versus repeated cross section sets `panel`. Sun–Abraham uses `aggregation="att"` or `"period"`; GRF uses `aggregation.target.sample="treated"` for ATT and `"all"` for ATE. Treatment-path normalization follows its specified per-unit target. These proposals appear in `design_change` when they change an adopted specification. Existing top-level fields remain available. `identification` is retained as source prose; its words never select a package. Selection records `executed=false` and leaves the adopted specification unchanged.

`target.kind` must match the selected mathematical target. A two-period DID targets ATT; an absorbing event study targets its stated ATT aggregation; a changing-path estimator targets the history contrast or normalized dose effect; sharp RD targets the cutoff effect and fuzzy RD additionally supports LATE. Forest CATEs and policy value use their respective branches. A partially linear coefficient implements ATE only with an explicit constant-effect restriction. The selector rejects a target outside that method's contract. Declared `continuity=false` rejects continuity-based RDD; `exclusion=false` rejects IV moments, instrument scores and their test inversion; `overlap=false` rejects selection-on-observables and policy/forest comparisons requiring that support. Fuzzy RD additionally requires exclusion and local monotonicity. The selector keeps adopted structured conditions when the request does not replace them. New results and selections carry `result_format_version=1`.

`official_implementation.execution_mode="external_official_entry"` identifies a verified official interface called from the existing project analysis. This mode does not claim a built-in runner execution. Heteroskedastic or clustered weak-IV inference selects the existing `iv_ar_robust` runner, which calls [`ivDiag::AR_test` 1.0.8](https://github.com/apoorvalal/ivDiag/blob/cbc391f4b1013c837743593bcde54efd5d733fb7/R/AR_test.R) with one endogenous treatment, excluded instruments, controls, fixed effects, weights and the adopted cluster columns. `options.args.CI=true` requests the official confidence set; `options.args.alpha` must agree with the requested confidence level. The function uses robust covariance without `cl` and clustered covariance with `cl`; its one-instrument implementation solves the quadratic inequality, and its multiple-instrument implementation uses a transformed whole-line search and boundary refinement. The runner preserves the returned endpoints, disconnected pieces, unbounded pieces and empty-set classification.

Supply the actual analysis columns in `inference.cluster` (one name) or `inference.clusters` (a list); the prose label `inference_unit="state"` names the economic unit and does not bind a column. The selector passes DID clusters to both `att_gt.clustervars` and `aggte.clustervars`, and passes robust IV clusters to `AR_test.cl`. DID accepts the entity column and one additional independent cluster. An explicit `comparison.confidence_level`, `inference.confidence_level` or `inference.alpha` sets the corresponding native level; conflicting level and alpha are rejected. A simultaneous DID family sets `cband=true` and `bstrap=true` at estimation and aggregation, whereas a pointwise family sets `cband=false`. Cluster-robust analytical inference remains available in did 2.5.1; clustering alone does not force a bootstrap. A two-period design requiring clustering or a level/family beyond DRDID's saved 95% pointwise output uses the existing group-time runner. The selector retains native changes in `option_changes` and marks changes to an adopted specification as proposals. The [versioned did interface](https://github.com/cran/did/blob/453a1be859411edc1c8933891940cb3a570d7095/R/att_gt.R) defines these arguments.

Each alternative's `eligibility.excluded_by` lists contradictions with the requested target, panel/history structure, dependence and required error model. `requires_identifying_conditions` means its listed conditions must be established from the economic design and observations. A compatibility match does not establish identification. For example, independent-unit DRDID inference is excluded for state-clustered sampling, and exact Anderson–Rubin F inversion requires explicit independent homoskedastic normal errors.

For clustered designs, `conditions.cluster_count`, `treated_cluster_count` and `common_shocks` accompany the assignment and inference units in `method_selection.inference.cluster_design`. Counts refer to the declared design and must match the fitted sample. The inference comparison returns the existing `wild_cluster_bootstrap` and `club_sandwich` entries with their supported saved-model classes, native options and required contrast/null. The former accepts the runner's saved `lm` or linear `fixest` fits; the latter comparison specifies `CR2` with Satterthwaite inference for a saved `lm`. Their official APIs determine each model's support. The selector applies no fixed cluster-count cutoff and preserves the adopted inference. It does not substitute linear-regression bootstrap or CR2 output for group-time DID or weak-IV test inversion. See [boottest.fixest](https://s3alfisc.github.io/fwildclusterboot/reference/boottest.fixest.html), [coef_test](https://jepusto.github.io/clubSandwich/reference/coef_test.html) and [vcovCR.lm](https://jepusto.github.io/clubSandwich/reference/vcovCR.lm.html).

For `fixest_ols`, `fixest_ppml` and `sunab`, an adopted cluster binding reaches a cluster formula in `args.vcov` with the actual cluster columns. The requested level reaches the runner's `confidence_level` and official pointwise `confint` calculation. A simultaneous family requires its own implemented inference procedure. For RDD, the same declared level reaches `rdrobust::rdrobust(level=...)` in percentage units; one independent cluster partition binds through `columns.cluster`. Fuzzy RD requires the actual receipt column in `columns.fuzzy` or the explicit native receipt vector. Missing receipt/cluster bindings remain in `unbound_inputs`. The selected RD result uses the official robust bias-corrected estimate and pointwise interval.

For `implementation="pyfixest"`, the conditional-mean selector passes the declared weight column and confidence level into the flat HDFE options and binds one cluster column to native CRV1 or the adopted CRV3. Its executable inference object uses the existing `robust` or `cluster` schema. A simultaneous interval family or multiple cluster partitions require their own implemented procedure. Native `weights_type`, `ssc` and covariance choices remain in the proposed specification and the adopted object remains unchanged.

For `implementation="grf"`, the selector binds a string `weights` column to `options.columns.sample.weights` and one `inference.cluster` column to `options.columns.clusters`. The requested confidence level becomes `options.confidence_level`. The official forest carries these observation weights and cluster assignments into its nuisance fits, forest estimation and `average_treatment_effect`; ATT selects `target.sample="treated"`, and ATE selects `"all"`. Native `equalize.cluster.weights=true` gives clusters equal population weight and requires omitted `sample.weights`; the default remains `false`. An unbound declared weight or cluster remains in `unbound_inputs`. Multiple cluster partitions and simultaneous intervals require their corresponding implemented procedure. The adopted specification remains attached unchanged, and changed native settings appear in the proposal.

For `implementation="econml"`, the existing `causal_forest` runner uses independent-observation folds, unweighted fitted-sample aggregation and 95% pointwise intervals. Selection binds `inference={"type":"forest"}` and rejects requested weights, dependent sampling, another level or a simultaneous family. The existing GRF route supplies its declared weighting, clustering and pointwise level options. For multi-arm policy evaluation, a declared weight-column change reaches `options.weights` in the proposed execution specification and remains an adoption change relative to the saved specification.

The selector also accepts the existing run fields `data`, `id`, `outcome`, `regressors`, `endogenous` and `instruments`, or recovers them from `adopted_specification`. For an existing causal runner, `official_implementation.execution_specification` returns its exact public run schema, proposed native options, required command and missing field/cluster bindings. `status="specified"` denotes completed input binding; the runner then validates the data and executes the official estimator. `adoption_required` preserves a changed adopted specification. External official entries retain their own constructor and output contract. `official_implementation.dependencies` resolves the existing registry's requirements resources and paths; those files remain the sole package-version authority. Bind selected pins and the requirement file through the existing research runtime, or use `runtime.requirements` when restoring its complete family.

The causal runner executes `doubleml.DoubleMLPLR` (partially linear slope), `doubleml.did.DoubleMLDID` (two-period ATT), `doubleml.DoubleMLIRM` (`ATE`/`ATTE`), `DoubleMLPLIV` (partially linear IV) and `DoubleMLIIVM` (`LATE`). The selector returns their bound run specification and the existing causal requirements. A requested Rust replacement MPEC returns the official `ruspy.get_criterion_function` contract with `init_dict.method="MPEC"` and its returned criterion, derivatives and Bellman constraints. BLP uses GMM; finite-state game selection accepts its implemented NFXP/MPEC; latent replacement uses EM; entry inequalities and share inversion retain their actual algorithms. `fixes::att` supplies the external `simple` aggregation when the requested fixes target is overall ATT.

For DoubleML scores, the selected constructor `score` is materialized in `official_implementation.options`. ATT sets `score="ATTE"`; ATE sets `"ATE"`, and the instrumental interactive model sets `"LATE"`. The [official IRM interface](https://github.com/DoubleML/doubleml-for-py/blob/a3493c3b7a444b6ddd730ad05c2c0e6c67ac19c3/doubleml/irm/irm.py) permits its `weights` argument only for the weighted ATE score. An ATT request with that constructor weight argument is rejected. Preserve sampling weights, target-population weights and residual-treatment weighting as distinct economic objects.

For `design="structural"`, `structural_model="finite_horizon_choice"` selects the official respy criterion for `target.kind="structural_parameter"`. `numerical.estimation_method="smm"` selects the weighted simulated-moment distance; `"maximum_likelihood"` selects the mean log likelihood. `structural_model="lifecycle_choice"` selects `lcm.Model.solve` and `Model.simulate` for `target.kind="policy_value"` or `"welfare"`, using `numerical.estimation_method="backward_induction"` and fixed or previously estimated parameters. These are `external_official_entry` contracts with `executed=false`. Their [finite-horizon and lifecycle input contract](../dynamic-models/finite-horizon.md#official-finite-horizon-and-lifecycle-selection) preserves states, actions, transitions, normalizations, seeds and aggregation. Lifecycle selection rejects `equilibrium` and structural-parameter estimation. Finite-horizon estimation rejects policy and welfare targets. Adopted specifications remain unchanged; proposed `return_scalar=false` supplies the official criterion's named output for saved diagnostics.
