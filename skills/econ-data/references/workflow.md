# Data execution operations

Select the required section from the [skill entry](../SKILL.md). Read that section and its mandatory dependencies completely before its operation.

## Equity evaluation

Use mode `equity` for stock selection, intrinsic value, structural competition, financial forecasting and updates from IR or news. Read the [equity workflow](equity.md) and its self-contained [model and valuation reference](equity-models.md), then execute the linked source-processing and numerical tools. Acquire company and market observations, estimate the identified model, solve competitors' responses, compute physical cash-flow forecasts and market-implied performance, and compare attainable investment decisions after taxes and costs. A stage without its requested real-company numerical result remains unfinished. Public execution uses public data and the current user's own credentials; private connections and saved records belong to that user. Keep the five existing specialist owners: econ-literature acquires evidence, econ-design selects the identified model, econ-data executes the calculation, econ-writing explains the result, and econ-review performs requested assessment.

## Procedure

### Execute structural estimation and equilibrium

Read the adopted [structural specification](../../econ-design/references/designs.md#structural-estimation-and-counterfactuals) and use [engine selection](implementation-engines.md#estimator-engine-and-algorithm-selection) and [numerical methods](implementation-numerics.md#numerical-methods) for its actual model. Carry parameter-to-moment identification, state/action timing, transitions, normalization and equilibrium selection into the installed specialist interface. Estimate, solve the baseline and changed equilibrium, and produce the requested prices, quantities, policies, profits and welfare from the same fitted primitives. Preserve the specification revision and scenario in the existing result objects. The existing demand and finite-state game implementations also serve research calculations through their documented `fit` and `dynamic` entry points.

### Map the object to the existing execution path

For requested reuse of an observed project command or environment repair, select `operational_procedure_reuse` and use the [existing experience helper](../../../harness/research.md#retain-and-reuse-an-observed-procedure). Match the actual producing run, applicability and current target authority before adopting its proposed steps.

For a repeated execution failure, recover the actual command, input versions and returned cause from the existing result record, then reuse a matching observed procedure through the experience helper. Use focused saved-log views and the [context packer's](../../../scripts/pack_context.sh) optional symbol map when they resolve the pending source lookup. An exact known owner goes directly to its current source. Preserve the complete mandatory instructions, adopted estimand, numerical conditions and required verification.

Locate the existing entry point, specification, input documentation and saved results for the requested operation. Use [implementation notes](implementation.md) for acquisition, data contracts, computation, prediction or numerical methods, [numerical dependencies and replication](reproducible-workflow.md) for saved analysis results, and [EXECUTION](../../../runtime/EXECUTION.md) for general file operations and [publication](../../../harness/publication.md) when that operation is requested. Read only the branches needed for that operation.

Map the requested economic object to records, fields, keys and transformations. When the intervention changes reporting, detection or recording, compare the recorded outcome with a source or stage that responds differently to that process. When a result constructs a classification or score, evaluate its target relationship with separate information. Preserve the source version, population, period, observation unit, quantity unit, denominator and adopted observation-status treatment. Choose joins that produce the intended population.

### Construct a requested data design

Inspect the source fields that define the proposed measures. Map sample eligibility, measurement support, scale, case mix, behavior and heterogeneity to their roles in the design. Define each requested metric's population, numerator, denominator, timing, aggregation and missingness treatment. Map the measured quantity to the outcome or resource use that ranks the proposed actions. Preserve each field's definition of amount due, amount paid, level, increment, conditional mean or population total; trace composition changes through the relevant counts or weights. Construct pre-treatment groups from pre-treatment information and fix membership across the comparison period.

Use the adopted variable roles from [econ-design](../../econ-design/SKILL.md) in the existing [assembly specification](research-data.md). Its `definitions` maps each economic variable to source fields, measurement, timing and construction; `analyses` binds those columns to the existing estimation inputs. Build the shared sample once with `assemble`; declare a separate analysis sample when its adopted population or outcome requires one. Pass the selected sample's hashed `data_record` to estimation and description, then carry the saved variable definitions, transformations and sample accounting into the result gallery and Writing. Change an adopted variable or sample through its existing scientific specification.

Retain an inspected data document at its existing source owner with its version and exact locator. Link the adopted definition and its source through [decision references](../../../harness/state.md#retain-and-retrieve-adopted-definitions); record the decision's reason and change authority in `adopted_decisions`. Use `state.py context` to retrieve the selected established definition on resumption, and apply the returned reference impact before changing its scientific consumers.

### Implement at the existing owner

For estimation, read [the estimator and package selection branch](implementation-engines.md#estimator-engine-and-algorithm-selection), match the adopted parameter to an official function and its supported options, and call that function directly from the existing analysis entry point. Confirm the installed interface before executing it. Carry the selected sample, weights, fixed effects, covariance and requested post-estimation output into the actual call; resolve an unsupported requirement through a matching implementation. Reimplement an estimator only after identifying the required feature absent from the available specialist implementations.

When an unresolved implementation choice governs many later fits or exhibits, execute its determining operation first: recover the requested contrast with its sample and population weights, or solve the changed equilibrium with its corresponding outcomes. Use an existing valid fitted object where available. Carry scenario-specific prices, shares, costs and policy assignments together into the decision quantity. Repair an unsupported call or mismatched object at its producer before expanding the dependent run.

Use the [implementation decisions](implementation.md#functions-types-and-failure-boundaries) for control flow, reuse, abstraction, file placement and error handling. [EXECUTION](../../../runtime/EXECUTION.md#project-file-ownership) owns file scope, callers and consumer updates.

### Select a specialized research calculation

Select the individual registered condition for the adopted calculation from `index --operation econ-data:execute`, then read its selected sections and required dependencies. Do not add a family-wide condition to an already identified method unless the request needs that coverage. For a bounded causal calculation, select the matching `method_causal_*` condition from the [operation registry](../../../registry/operations.json). Its conditions load the common input/result contract and the relevant method section. `method_extended_causal` retains the complete causal reference for family-wide work and existing callers. Each interface accepts the declared scientific inputs, invokes its calculation engine, and saves fitted quantities, adopted definitions, numerical checks and named statistics for the same research DAG.

| Calculation | Registered condition | Model and execution contract |
| --- | --- | --- |
| Causal and empirical models | [Select the registered condition](../../../registry/operations.json); `method_extended_causal` selects the complete family | [Causal models](../../econ-design/references/causal-models.md): fixed effects, IV and weak-IV sets, staggered DR-DID, RDD, synthetic controls, dynamic panels, causal forests, policy evaluation, network/spatial designs and limited outcomes. |
| Demand, supply and market design | Individual `method_market_*`; `method_extended_markets` for family coverage | [Market models](../../econ-design/references/market-models.md): joint PyBLP estimation, endogenous prices/characteristics, equilibrium interventions, auctions, search, bargaining, platforms and matching. |
| Dynamic choices and games | Individual `method_dynamic_*`; `method_extended_dynamic` for family coverage | [Dynamic models](../../econ-design/references/dynamic-models.md): observed panels, stationary and finite choices, CCP, simulation moments, game inequalities, sequential estimators, continuous time, hidden types and dynamic demand. |
| Macro and heterogeneous agents | Individual `method_macro_*` or `method_dsge_*`; `method_extended_macro` for family coverage | [General equilibrium](../../econ-design/references/macro-models.md) and [stochastic equilibrium](../../econ-design/references/dsge-models.md): observed productivity, equilibrium paths, lifecycle policies, Sequence-Space Jacobians and policy welfare. |
| Agent simulations | `method_agent_simulation` | [Agent models](../../econ-design/references/agent-models.md): trade, learning, conservation, fixed interventions and result-dependent next experiments. |
| Numerical kernels | Individual `method_numerical_*`; `method_extended_numerics` for family coverage | [Numerical methods](../../econ-design/references/numerical-models.md): finite games, clearing payments, state prices, binary-logit moments, finite SIR paths, queue capacity and decision-right equilibria through their existing numerical functions. |

Use `research_data_discovery` for [official data acquisition and declared analysis tables](research-data.md). Use `research_adaptive_experiments` for [source-backed candidate proposals and result-dependent experiments](../../econ-design/references/adaptive-research.md). Their commands consume the existing state, files and stage receipts. Select `research_result_artifacts` to [register saved statistics and generate articles and slides](../../econ-writing/references/result-artifacts.md). Restore only the selected family's pinned requirements with its declared Python version. respy, pylcm and Dolo each use their own compatible environment; the causal family uses its pandas 3 environment. Bind that interpreter and requirement file to the existing analysis stage. Preserve the project's existing infrastructure, Pixi and R environments.

### Produce the result by dependency

For an adopted local analysis DAG, execute the [research runner](../../../harness/research.md) with its explicit sources, scripts, helpers, environment, specification files and consumed output IDs. Bind an existing governing task with `--parent` so its original request, decisions, scope and holds govern every stage. Its immutable generations and existing state receipts identify completed calculations, selective rebuilding and the files consumed by tables, figures and prose. Declare the actual Python, R or Julia runtime and selected package closure for environment-aware reuse, and choose a named development/formal profile when the adopted execution paths differ. Build the requested reproduction package from the exact current saved stages through the same guide. Use the [causal runner](../scripts/research_causal.py) for the selected official DoubleML score, GRF effect target or randomizr experiment. Select `method_causal_doubleml`, `method_causal_grf` or `method_rct_design` to read its complete scientific contract. The [estimation interface](../scripts/research.py) retains its supported OLS, IV, partial linear orthogonal-score and two-period panel DID inputs; it calls the official specialist engines and preserves fitted IDs, named estimates, covariance, actual fold assignments and inference. Restore its [declared numerical dependencies](../scripts/requirements-research.txt). Use the existing `equity.py fit` and `dynamic` interfaces for their adopted structural models and call another selected specialist directly when its economic object requires it.

Trace the requested result through its source, derived data, analysis object and exhibit. Reuse completed saved objects with matching dependencies; when an input, mapping, population or specification changes, recompute affected descendants. Generate tables, figures and numerical prose from the same selected quantities under the [result lifecycle](reproducible-workflow.md#carry-analysis-results-into-tables-figures-and-prose). Keep dependency versions and stochastic seeds in the existing records.

Keep adopted sample rules and classifications in the canonical specification. Identify a proposed specification change and the sample membership, quantities and consumers it affects; apply [CORE](../../../runtime/CORE.md) to authority. Keep unresolved choices and project status in operational records.

### Power and estimator simulation

For a requested power, minimum-detectable-effect or estimator simulation, match the DGP, assignment unit and dependence to the adopted estimand and test. `research.py power` implements the documented two-arm Gaussian pooled-t individual/cluster design, its noncentral-t power and MDE, and seeded Monte Carlo bias, RMSE, rejection, coverage and simulation uncertainty. Preserve the specification, code and runtime identities. Use another adopted estimator/DGP for DID, IV or structural power; the two-arm calculation does not justify their inference. Compare a valid case with the consequential violated restriction when assessing a method.

### Specification search and recovery

For specification search, freeze the target, population, sample, evaluator, inference and discovery/validation/holdout partitions in the adopted protocol. Expand its finite parameter grid through the same runner, compare the declared metrics and execute the selected next branch. Use `research.py evaluate` for fixed-split OLS or Ridge prediction with train-only preprocessing. Choose a causal specification through its identifying restrictions and target parameter, and apply its adopted diagnostic comparison. Preserve unsuccessful candidates and their actual returns. Read [recovery and procedure reuse](../../../harness/research.md#recover-interrupted-attempts) before reconciling a killed process or reusing an observed repair; the current task retains its authority and fixed scientific choices.

### Finite-horizon macro calculation

For the finite-horizon representative-household growth model, use [the macro solver](../scripts/research_macro.py) with explicit initial and terminal capital, productivity, output-tax paths, calibrated parameters and residual tolerance. It solves positive consumption and capital choices, returns scenario-specific paths and welfare, and checks the original Euler/resource equations and analytic derivatives. Select the specialist package and observation map for another adopted macro model through the existing engine-selection procedure.

### Descriptive statistics

For descriptive statistics, start with the economic question and choose the population, analysis unit and summary under [descriptive choices](implementation-descriptive.md#choose-descriptive-statistics-from-the-question). Apply the adopted available-case or model sample and record or entity weights. Save the counts, denominators, weights, population, period and units that reproduce each summary. State a rate's or mean's denominator in its unit, axis, heading or defining text. Include sample and observation-opportunity differences that determine the comparison and state shared definitions once. Compute and display the summaries that answer the question.

### Check the changed calculation

Apply CORE's completion rule through [changed calculations](implementation.md#compare-changed-calculations) to the affected keys, joins, sample, weights, formula or interface. Preserve input contracts, statistical inference and numerical convergence inside the research calculation.
