# Adopted request and instruction contracts

`requirements_check.py` owns source-contract validation and evaluation of its declared requirements. `validate_contract(contract, request_bytes)` preserves the original request hash, exact source spans, adopted deliverables and prohibited operations. `missing_requirements` evaluates current artifact bytes, the final message and source-verified action results. `state.py bind-specification` owns the retained binding and its authorized revisions.

The contract accepts schema versions 1 and 2. Each requirement identifies its source text and an artifact, action, content, prohibition or evidence condition. Version 2 can pin inherited instruction bodies through paired `sources` and `request_source_id` fields. Each source carries its ID, version, exact UTF-8 content and SHA-256; the request source matches the actual request bytes. Source spans use Unicode character coordinates.

Artifact paths must be safe, distinct and relative. Completion requires each declared artifact to have a registered file output whose version matches the current file bytes. The evaluator enforces its declared file type, `nonempty` setting and case-insensitive `reject_placeholders` markers. JSON rejects duplicate keys and nonfinite constants; PDF and ZIP/Office inputs retain their signature, member and inspection-budget conditions. Action requirements need an exact operation/target match with a current successful native return. Source files available through `evidence_refs` have their own namespace and never supply a missing output.

Content, prohibition and evidence conditions consume their exact `artifact://PATH`, relative artifact path or `message://final` target. `exact_sections` counts the requested heading level through the existing Markdown section parser, including ATX and setext headings outside fenced code. `contains_literal` and `forbidden_literal` compare the declared string with exact UTF-8 target text, preserving case. `json_field` checks RFC 6901 pointer presence, including a present null value; array indices use canonical nonnegative integers. Missing, unreadable, unregistered or unsupported target content leaves the requirement unmet.

Every `evidence_refs` entry requires a current nonempty source file. Existing task input pins must match when present. An optional `id` selects a record in that file's JSON `records` array, whose IDs must be unique nonempty strings. Evidence conditions also consume the current target bytes. The contract retains source identity and availability; it supplies no citation-location syntax. `forbidden_operation` rejects a matching recorded operation and target, including an unsuccessful operation, and remains enforced at the existing modifying-operation preflight boundary.

`state.py missing_required_results` collects the current registered outputs and evidence, reads the hash-bound specification through `_spec_inputs`, and invokes this same evaluator through `native_check.requirements`. State completion evaluates the uniquely identified registered final-message body when a message condition is declared. The ordinary Stop callback supplies the actual host final message and applies the same evaluation to the bound task and completed ancestors. A changed final message is evaluated before return. Failed requirements appear in the existing completion failure; no report or additional receipt is created.

An optional existing `traceability` array retains requirement, task, code, check and decision references so persisted user contracts remain readable. Its `check_ids` can be empty when the adopted contract selects no separate check. Requirements containing only final-message conditions remain supported.

The evaluator reads the declared targets and sources and executes no development command. CORE and PROSE govern the integrated judgment of meaning and instruction adherence. Explicitly selected independent certification uses the existing state evidence interface.
