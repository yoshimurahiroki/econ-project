# Choose the next research operation

Use this resource when the method, economic comparison, identification argument or ordering of dependencies is unresolved. Inherit [CORE](CORE.md)'s task boundaries. If established inputs and methods already determine the requested operation, execute it directly.

## Turn the question into an operation

Identify the decision-maker, options, objective, constraints and unknown quantities, and which proposition or choice the output changes. Express an unresolved problem in the general form that selects its operation: choice among feasible alternatives, identification of a quantity, aggregation over a defined population, constraint satisfaction, or coordination of dependent outputs. Add equations only when they determine the comparison, feasible set or next computation.

For an economic mechanism, identify actors, objectives, incentives, constraints and information. Include strategic responses, equilibrium adjustment and distributional consequences when they change the answer. Use the relevant sections of [design methods](../skills/econ-design/references/designs.md) for the actual construction or derivation. For observation maps, counterfactual objects and set-valued predictions, use the matching section of [economic analysis and models](../skills/econ-design/references/designs.md).

Ask whether exact knowledge of a missing quantity would resolve the choice. If the objective or decision rule would still be missing, settle that dependency first. Before collecting more data under a new assumption, determine whether existing information under the same assumption already answers the question.

## Separate explanations with a comparison

State what each remaining explanation predicts under the same inputs. Choose the population, time, choice boundary or observable where those predictions differ. Perform the comparison that distinguishes them. For a numerical comparison, set a tolerance from the difference that matters to the decision. For a fault diagnosis, vary the suspected cause in a small case while holding other inputs fixed.

When a representation or aggregation changes, preserve the target object, observation unit, feasible choices and decision-relevant distinctions. A different mean or population is a different estimand even when it uses the same records. Read [data implementation](../skills/econ-data/references/implementation.md) only for the relevant measurement, sample, join, estimator or numerical operation.

## Select a feasible action

Compare candidates under the same objective, resource constraints, population, period and units. First remove candidates violating binding constraints and those dominated under the same conditions. Rank the remaining options by contribution to the requested objective; do not add unlike objectives into an unexplained score. For equivalent outcomes, choose the option requiring fewer additional resources and connecting to adopted definitions. Prioritize comparisons that change the central proposition, identification or feasibility; method novelty and a larger menu are not adoption criteria. Select the highest-ranked feasible candidate when the ordering is determined and carry it into the next authorized operation.

If the same option wins across the admissible range of an unknown value, execute it. When the ranking changes within that range, state the switching condition. Retrieve that value when the task authorizes the source work and its attainable result can change the action. Otherwise return the conditional selection and the determining input. Do not replace a resolvable choice with an unranked menu or a request for more information that cannot alter the choice.

## Source integration and method selection

Establish institutional facts that determine feasible actions, information, eligibility or timing from the applicable source versions. For time-dependent facts, use the version covering the claimed period. If a determining fact remains unavailable, derive implications under explicit alternative values or identify the needed input.

Before adopting a searched conclusion, formulate the target, feasible actions, information and constraints from established facts and explicit assumptions. Derive the implication that answers the target or separates the alternatives. Keep that implication in the existing work context and use it to direct the source lookup.

Search for methods when an unresolved assumption, target mismatch or trade-off changes applicability or selection. Compare methods on the same target, action space, data, information, assumptions, decision value and resource cost. Map the selected method’s assumptions and target to this problem before applying it. Before another lookup, identify internally which result would choose action A and which would choose action B. If A and B are identical, skip the lookup. When source research itself is requested, stop on coverage of the requested sources and questions. Stop method discovery when that choice is resolved; reopen it only for a new determining condition.

## Resolve dependencies and integrate findings

Each partial task must complete a named parent proposition, choice or artifact. Reuse the parent's formulation when the target, constraints and decision criterion stay the same. If any changes, formulate that subtask's general problem and select the judgment and operation needed to resolve it. Return the result at the granularity the parent needs. Sequence prerequisites and reuse numerical outputs whose inputs and definitions match. Apply [TEAM](TEAM.md) when the benefit of independent work exceeds briefing and integration costs.

When the task requires independent reasoning alongside source findings, share the question, definitions and fixed facts while keeping developing conclusions separate until integration. Compare the proposed implication with the observed or calculated result. Compare analytical and source results using the same estimand, units, population, timing and assumptions. Reconcile disagreements at their determining passage, equation or input; update the affected premise and descendants. Keep unaffected choices and outputs.

Return the selected design, comparison, implication or next executable operation. End this research step when that dependency is resolved. Additional formalization, source collection and alternative enumeration require another unresolved dependency within the task.

## Operational plans

For a requested operational plan, specify responsible actions, handoffs, needed cooperation and completion conditions within confirmed actor time and resources. Define each stage's inputs, sources and update triggers. Derive success conditions from the requested target state and supplied acceptance criteria; preserve the distinction between reaching a target level and improving from a baseline.

Use only the requested adoption or release conditions. Preserve required frequencies. Reuse existing records and routines. Include a new record, check, meeting or cadence only when the user requires it or a concrete decision or corrective action needs it. Remove unnecessary operations before drafting and deliver the actionable plan without a selection-process narrative or an added audit checklist.
