# Execute scoped operations

## Select the operation and working area

1. **Output: scoped change; consumer: implementation.** Identify target, authority, instructions and existing edits. Keep temporary work outside deliverable destinations; inspect the owning function/passage, callers and consequential dependencies with scoped `rg`. Change producer and consumers together under the [implementation rules](../skills/econ-data/references/implementation.md#functions-types-and-failure-boundaries); stage owned changes and keep credentials in authorized storage.
2. **Output: executable inputs; consumer: runner.** Use the supported operation and root. Bind scripts, specifications, referenced inputs, consumed outputs, interpreter and used packages/executables. Preserve configured project connections. Use a simple command for a short chain or existing dependencies for selective rebuilding; establish scientific inputs and official interfaces before costly execution.

## Compare changed outputs

1. **Output: affected dependency set; consumer: rebuild.** Trace changed scientific inputs through definitions, official interfaces and consumers. Preserve sample, keys, multiplicities, target, units, inference and original tolerances. Reuse calculations for presentation edits.
2. **Output: inspected display; consumer: delivery.** Render and inspect requested PDFs, slides or figures through their existing owner. Versioned writing binds source, specification and manuscript through econ-writing; activate paragraph execution for requested correspondence or persistent dependencies.

## Complete outputs and failure propagation

1. **Output: complete generation; consumer: downstream operations.** Use [publication](../harness/publication.md#complete-generation-boundary), retaining the preceding result on failure. Propagate child failure/interruption and retain diagnostics in the existing record. Repair the actual argument, network, input or target error. Resume matching documented restart inputs or rebuild affected descendants; TEAM owns interrupted external writes.
2. **Output: observed operation result; consumer: CORE review.** Inspect actual returns and requested destinations: saved quantities, Git repository/branch/parent/commit, or plugin identity/release/readback. Retain running/submitted status until actual completion. Bind files to the resolved producer or scientific owner; compare changed targets and relevant outputs. Before: “The file exists, so the run succeeded.” After: “The producer returned success and saved the requested quantities at the adopted destination.”

## Record and artifact boundaries

1. **Output: continuation inputs; consumer: next operation.** Keep status in existing context, scientific definitions in the specification and provenance with the result. Use [state](../harness/state.md) for persistence and the [distribution contract](../docs/ai/integration.md#distribution-contract) for instruction maintenance. Reuse scientific results across record-format-only changes.
