# Execute on identified inputs and outputs

Use [CORE](CORE.md) for authority, full required reading, substantive review and completion. Read [publication](../harness/publication.md) for an authorized move, Git write or complete multi-file publication. Use [state](../harness/state.md) when the operation needs persistent continuation or saved-result reuse.

## Select the operation and working area

Classify the operation as answer, modify, create or external. Assign write scope to changes. Inspect project instructions, owned paths and existing edits. Keep temporary output separate from requested destinations. CORE owns authority and preserved inputs.

Determine the route from the current tool schema, target and permissions. Prefer the supported purpose-built operation. Diagnose its actual return: an argument error, network failure and target denial require their own repairs. Use another authorized route when it implements the action within the same authority. Prior access or an absent command establishes no current capability.

Git staging, commits, remote writes, installation and configuration changes use the request's corresponding authority. Stage owned changes and keep credentials in their existing authorized storage. Complete a replacement before publication; failure preserves the preceding complete result under its original identity.

## Checks and completion

Apply CORE's integrated review and three-condition rule to the changed input, required result and producing operation. A display change reuses its calculation; a scientific input change invalidates affected consumers.

For computation, match sample, named quantities and saved files to the successful run. For Git, match repository, branch, parent and returned commit. For plugins, match identity, expected release, returned release and changed source. A submitted or running operation remains at that stage. Existing state records retain actual action evidence without adding approval authority.

## Compare changed outputs

Trace a changed formula, sample, weight, encoding, estimator, inference or numerical scheme through its adopted definition, official interface, implementation and consumers. Preserve identifiers, keys, term names, population and original convergence conditions. A join uses the declared keys and multiplicities. A requested reproduction uses its specified source data and reference quantities.

For names, comments, paths or presentation, inspect affected callers and consumers. Render requested PDFs, slides and figures through their existing workflow and inspect the final output. Repair the source of a mismatch and regenerate its descendants.

For routing, rule loading, distribution and state interfaces, use the selected entry point and complete required bodies. Inspect the generated and saved output at each requested destination under CORE's completion rule.

## Project-file ownership

Use `rg --files` and scoped `rg` to locate the existing entry, owner and dependencies. Read the complete changed function, imports, relevant callers, state and consumers. Check ancestor instructions at their actual paths. Use an available symbol tool when dispatch or name collisions require it.

Change the canonical producer and update its imports, links and consumers together. Use [econ-data's implementation rules](../skills/econ-data/references/workflow.md#implement-at-the-existing-owner) for ownership, control flow, abstraction and removal of superseded code.

## Entry point and dependencies

Use the project's existing runner and declared execution root. Bind source files, scripts, helpers, specifications, consumed outputs and the selected environment. Include files referenced inside specifications. Keep dynamically selected packages and external executables in that environment's declared dependencies. Match Python, R, Julia and SQL engines to their actual interpreters and installed packages.

Use a simple command for a short chain and the existing dependency system for selective rebuilding. Reuse matching completed calculations. Keep machine-specific paths and private connections in existing configuration. Preserve reproducible source versions and access instructions on transfer.

Save completed changes through Git at the requested frequency. Establish scientific inputs and the official package interface before a costly run. CORE owns continuation records and authority.

## Complete outputs and failure propagation

Use [publication's complete-generation boundary](../harness/publication.md#complete-generation-boundary) for atomic files, linked output sets, concurrent writers and preservation of the preceding result.

Use child exit status, actual required outputs and input/specification versions to determine success. Propagate interruption and failure to affected dependents. Stream process output through the host or retain the bounded diagnostic needed by the existing result record; add no separate log or history system. CORE's task-entry protocol owns recovery of truncated source/rule reads.

After repair, resume at the failed stage only when its prerequisites still match. An upstream change rebuilds its affected descendants. Keep partial files unpublished. A stage resumes inside its documented complete restart boundary or reruns into a fresh destination. Reconcile the actual target before retrying an interrupted external write under [TEAM](TEAM.md#retry-and-capacity).

### Example: replace one output after a complete write

Write and close a temporary file beside the destination, then publish it with `os.replace`. On failure, clean up this invocation's temporary file. Use the existing publication helper for linked metadata, concurrent writers or crash durability.

## Record and artifact boundaries

Keep operational status, unresolved user choices and continuation state in existing operational context. Keep scientific definitions in the adopted specification and numerical provenance with the producing result. Research prose presents its economic argument and quantities; a requested plan or handoff presents its actual operations and dependencies.

For instruction maintenance, compare each actionable rule with its owning code and actual execution path. Edit the canonical instruction or producer and regenerate affected consumers once. Use that generation for deployment. A record-format change alone does not invalidate scientific content or calculations.
