# Shared work, resumption and handoff

## Native model roles

The lead permanently owns the question, adopted specification, decisions, integration and final result. The five research specialists retain subject ownership; execution roles are independent of provider and model.

| Role | Assigned work |
| --- | --- |
| lead | Formulate, decide, decompose, integrate and finish; resolve an independently assigned question as a child lead. |
| implementer | Implement a bounded change or calculation under the adopted specification and file ownership. |
| retriever | Search, extract, classify, compare recorded fields and convert formats through a settled procedure. |
| specialist | Resolve the consequential hard core remaining after substantive lead attempts and cause-specific repair. |

The parent chooses a role from the task, independence, workload and downstream use. It selects an available model and reasoning setting through the host's actual launch schema. Inherit the host model by default; apply a supported per-role override when selected. Local Codex or Claude configuration does not configure ChatGPT Work. Legacy Sol, Terra, Luna and Astra correspond to lead, implementer, retriever and specialist; names confer no additional authority. The existing OpenAI choices remain an explicit Codex preset through [configuration](../docs/ai/config-templates/README.md#native-roles-and-model-selection).

A lead may assign an independent question to a child lead, bounded implementation to an implementer and settled retrieval to a retriever. An implementer may delegate related retrieval. A specialist may delegate calculations and retrieval required by its assigned core. A retriever cannot delegate. Normally use at most two delegation edges and the host's actual shared concurrency limit, including waiting parents and any bridge. Reserve capacity for a needed descendant. Without nesting or capacity, return the dependency to the parent for reassignment or sequential execution.

Assign the specialist after the lead has attempted the consequential problem, inspected the failure and tried a justified repair or alternative under the adopted target. Pass those actual attempts, the unresolved mechanism and dependent result. Length, broad complexity, ordinary review and a first failure do not establish that assignment. A host-selected primary may perform the lead role directly. If a selected native route requires a bridge lead, preserve the primary's actual identity and count the bridge in capacity.

Use fresh child context with the parent question, central obstacle, original source references and versions, fixed specification, authority, scope and completion condition. Every child reads the applicable AGENTS entry, CORE, PROSE, TEAM, selected operation/skill and activated dependencies in full. Model selection and compression preserve these obligations. Report observed model/provider/effort only from host fields; a requested model, role label or self-description supplies no runtime observation.

## Shared work

Delegate an independent contribution when useful parallel work exceeds briefing, coordination and integration cost. Keep short work and tightly coupled judgments with their current owner. Assign one writer per file or explicitly disjoint region; coordinate shared sessions, tabs, transactions and external targets as well. Separate conversations do not isolate resources.

Each assignment names the parent result it resolves, determining obstacle, exact inputs, source/rule versions, binding constraints, write scope, actual output and downstream consumer. Preserve settled choices and mark only decisions delegated by the request. A child cannot change the governing specification or authority; it returns that dependency to the parent. Sequence prerequisites and parallelize independent reads or isolated changes. Do not create a second manager, state store, progress ledger or review agent.

## Return and integration

Return the substantive finding or completed change, its implication, changed paths, producing inputs, artifact versions, source evidence, actual operation returns and remaining dependencies to the direct parent. Keep large artifacts in their existing owned paths. Match each return to its assignment and source version; arrival order does not establish correspondence.

The parent reconciles definitions, units, population, assumptions, interfaces and authority before use. Repair mismatches at the producer. Reuse matching completed results and continue the original outstanding outputs. A child closes only its own assignment. Give the user one integrated final response.

Progress updates state a determining result, failed dependency or next operation that affects completion. Keep coordination in the current conversation or existing task record. Do not add meetings or parallel status files.

## Retry and capacity

After an interrupted external write, inspect the same target and actual operation status before retrying. Repair a returned cause within existing authority and retry the affected action. Preserve completed independent work. Select worker count from actual available capacity and separable work.

## Resumption

Restore the original request, central problem, adopted constraints, authority, governing rule bodies, completed results and next authorized operation. Use summaries to locate their authoritative sources. Read changed text, text never read, and required bodies lost from active context. Preserve exact scope and priority; a summary or model change grants no amendment.

Reuse saved outputs only with matching consumed versions. Reconcile returns produced under earlier instructions before integrating them. When persistence is needed, use the [existing governing context](../harness/state.md#governing-context) and [saved-work lookup](../harness/state.md#find-saved-work). Preserve the source permitting an authorized amendment and update its affected consumers. Reuse an observed procedure only when its actual inputs and failure mechanism match the current task.

## Handoff

Transmit the objective, fixed constraints, authority, source versions, completed results and remaining authorized work. Point to the complete canonical instructions, specification and outputs. Include the parent proposition, adopted decision, permitted switching condition and exact essential user input for the next action.

## Requested usage accounting

Collect cost or usage only when requested. Use native launch/return fields and existing outputs; the existing `state.py usage` importer deduplicates cumulative observations. Retain actual role, requested/observed model and effort, start/finish and exposed token/usage fields with their sources. Never manufacture runtime telemetry, rates or subscription percentages. For a requested solo/team comparison, preserve equal inputs, specification, completion conditions and observed resources, including briefing and integration.

## Review findings and independence

Use independent review only when expressly selected or required by the platform. Preserve requested scope, identities and source evidence. Add no standing approval role or publication gate. CORE's integrated substantive review remains with the task owner.

## Paragraph assignments

Assign coherent arguments or sections with distinct sources. The editorial owner integrates terminology, evidence and logical dependencies, then completes CORE's review. Delegated and single-author writing use the same econ-writing workflow.
