# Shared work, resumption and handoff

Inherit [CORE](CORE.md). Read only the sections required for an active delegation, resumption, accounting request or handoff.

## Shared work

Keep one final result owner. Delegate a subtask when independently defined work yields a benefit greater than briefing, coordination and integration costs. Keep repeatedly interdependent intermediate judgments with the same owner. Consult the actual runtime's capacity and running assignments before launching work; reuse an active assignment for the same result. Label intentional replication or independent review.

Provide the worker with:

- parent_goal and assigned_result: the inherited parent objective, settled decisions and assigned dependency.
- finish: the applicable completion conditions.
- input_refs_and_versions and adopted_definitions: input identifiers and versions, relevant source passages, economic objects, units and determining assumptions.
- The selected method source and applicable rule references; for prose, reader, language, medium, length and selected profile.
- authority_and_holds: permission boundaries, holds, stops and release conditions.
- write_scope only when writing is assigned. Read-only answers need no invented output path.

Add a comparison question only when an unresolved judgment needs it. The worker inherits these settled boundaries and performs its assigned operation without a separate intake, general plan or redefinition of common rules. Give each writable output one owner and separate concurrent write ranges. Use the project's existing dependency graph for computational prerequisites and invalidation. Record actual worker/session identifiers when coordination or resumption needs them. Distinguish requested settings from confirmed capabilities and runtime state. Claim independent context or access isolation only when the actual setup establishes it.

For independent judgments, share fixed facts and definitions while keeping developing conclusions separate until integration. Add a reviewer only for a requested assessment or a specific unresolved disagreement requiring that judgment. Explicit blinding, sealed-artifact and release conditions remain binding.

## Return and integration

Return the assigned conclusion or artifact first, then its consumed inputs and definitions and the passage, comparison or calculation that determines it. For file work, include changed paths and versions; for execution, include the returned operation status. Include an unresolved dependency or deviation when it changes integration or the next action. Ordinary support returns use the conversation or existing record, without a new handoff document.

The owner matches input versions, scope and completion conditions before integrating. Resolve conflicts at the determining source or calculation. Return only mismatched portions to their owner, retain unchanged results and update affected descendants. Stop work whose result no longer advances the task.

## Retry and capacity

Use the task's permitted environment, account allowance, model settings and resources. A runtime change must remain within existing authorization. Retry after correcting a demonstrated input or configuration cause, or after runtime state shows a transient failure has cleared. Repeating an identical failure with identical inputs does not advance the dependency.

Preserve user-specified attempt, cost and resource ceilings. Use actual runtime capacity; do not invent common worker-count, depth or attempt caps. If the remaining remedy requires new authority, return the specific operation and blocker while continuing independent work.

## Resumption

Use the existing task store or conversation. Preserve completed outputs, consumed input versions, active dependencies, authority, holds and the next authorized action. Keep adopted study specifications in their canonical record and numerical provenance with the generating result. A progress-record locator is not a computation input unless its substantive definitions govern that computation.

On resumption, reconcile active workers and saved result versions before creating replacements. Reuse matching outputs and reopen only affected dependencies. Follow [state contract](../harness/state.md#state-and-version-contract) for the state contract and [local helper interface](../harness/state.md#local-state-helper) when a local store is involved. Preserve outputs while migrating records; perform only the missing required checks.

Keep local state, transcripts and authenticated settings out of shared receipts, exports, build contexts and public artifacts. Preserve private locators only in approved storage and transfers.

## Handoff

For an explicitly requested transfer or a needed continuation checkpoint, summarize from existing records:

- Current conclusion and completed artifact identifiers and versions.
- The requested remaining result and its completion conditions.
- The next operation and the consumed inputs, definitions and methods it needs.
- Confirmed execution state, active assignments and relevant unresolved dependencies.
- Permissions, holds, stopping conditions and the condition for proceeding.

Use the requested format. Identify the research artifact separately from operational continuation information. A transfer does not restart intake, enlarge permissions or release a hold. Produce a separate document only when the requested transfer format or actual persistence need requires one.

## Requested usage accounting

Use the runtime's returned counters and preserve raw events locally. Associate cumulative counters with their producer, epoch and chronological order; create a new epoch only after a confirmed reset. Distinguish observed values from unknown baselines, missing fields and unclassified resets. Cached input is part of input and reasoning output is part of output when the producer defines them that way. Label API-equivalent cost estimates as estimates; use invoices for billed charges.

## Review findings and independence

Use a different worker or session for a requested independent review. Record its actual identity and established context separation, never a self-assigned alias as evidence of another agent, and the review question: execution, support for claims or derivations, editorial usefulness or comparison. Establish context freshness and prior exposure when the requested independence depends on them.

Supply the raw result, source inputs, task and applicable constraints. Withhold the method condition and prior verdict for a blinded comparison. Restrict exposure or stage reader impressions only when the explicit protocol requires it. Label review of one’s own output as a self-check. Preserve protocol-bound sealing and release barriers.
