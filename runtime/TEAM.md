# Delegation and continuation

## Native model roles

1. **Owned decision → role.** The lead retains question, specification, adoption, integration and completion; Skills retain subject ownership. Match the remaining operation to this provider-independent table.

| Role | Model selection and effort | Input → output → consumer | Delegation |
|---|---|---|---|
| Lead | Host Terra-class model; high | Original request and economic frame → adopted question, judgment and integrated result → user or parent | Child lead, implementer, retriever |
| Implementer | Host model or supported lighter model; xhigh | Fixed specification, inputs, write scope and completion criterion → calculated/edited artifact and verification → lead | Related retrieval |
| Retriever | Lightest supported model for the settled operation; xhigh | Exact sources and extraction/conversion target → source-bound return → assigning owner | Return dependencies to parent |
| Specialist | Terra-class or Astra model; highest supported effort (xhigh) | Consequential unresolved core, substantive lead attempts and cause-specific repair → determining derivation/calculation → lead | Related calculation/retrieval |
| Independent reviewer | Fresh context; inherited supported model; high | Stop assignment on a turn with user-facing prose or explicit user review request → evidence, finding/repair and actual review return → lead | Return dependencies to parent |

2. **Role choice → native launch.** Inherit the host model by default. Apply a supported authorized override when capability, cost or completion time improves the assignment. Read the actual launch schema and available model/effort values; put the selected settings in those fields. Preserve tighter host/user settings. Retain requested settings and actual returned identity separately in the existing context. Before: “Label this worker a specialist.” After: “Send the unresolved Bellman residual and prior repair; set the supported model and highest supported effort in the native launch.” Length, routine review, general complexity or a first failure alone does not justify a specialist.
3. **Capacity → executable assignment.** Apply [host nesting and capacity](../docs/ai/config-templates/README.md#native-delegation-limits) to the whole hierarchy. Retrievers and independent reviewers return dependencies to their parent; available capacity determines the parent's next launch or sequential operation.

## Shared work

1. **Output: bounded assignment; consumer: worker.** Delegate separable work whose benefit exceeds briefing/integration. Every assignment carries the worksheet path and the section it serves; the worker follows the same procedure for its part, and the SubagentStop hook checks its return. Supply parent result, obstacle, exact sources/rules, fixed specification, delegated choices, write scope, output, consumer and completion condition. A specialist also receives actual lead attempts, repair and unresolved mechanism.
2. **Output: executable worker context; consumer: assigned operation.** Use fresh bounded context and one writer per file/disjoint region; coordinate shared sessions/targets. Each worker reads original applicable AGENTS, the economist's procedure, WRITING, TEAM, specialist and activated prerequisites.

## Return and integration

1. **Output: worker return; consumer: direct parent.** Return substantive result/implication, changed paths, producing inputs/versions, evidence, actual operation returns and remaining dependency. Keep large artifacts in owned paths.
2. **Output: integrated parent result; consumer: delivery.** Compare the return with assignment and original deliverable; reconcile estimands, units, population, conditions, authority and interfaces. Repair mismatches at their producer and complete dependent work. The parent owns completion and one integrated response; keep coordination in existing context.
3. **Output: next executable action; consumer: current owner.** Progress reports identify a determining result, failed dependency or consequential next operation. Before retrying interrupted external writes inspect the actual destination and repair the returned cause; retry the affected action while preserving completed independent work.

## Resumption

1. **Output: restored task; consumer: resumed operation.** After compaction, resumption, model change or handoff recover the original request, central problem, fixed specification, authority, completed results and next authorized action. Read original applicable bodies under [ECONOMIST](ECONOMIST.md); reuse matching consumed versions.
2. **Output: reconciled handoff; consumer: next owner.** Include canonical source/output paths, parent proposition, adopted decision, permitted switching condition and essential user-held input. Reconcile older worker returns. Resume interruption on actual user continuation; preserve terminal cancellation/completion. Use existing [governing context](../harness/state.md#governing-context) and [saved work](../harness/state.md#find-saved-work) for persistence.

## Requested usage accounting

Collect requested usage from actual host fields and outputs through the existing [usage interface](../harness/state.md#observed-execution-usage). Retain source-backed roles, requested/observed model and effort, time and exposed usage; invent no telemetry, price or subscription percentage. Compare solo/team work under equal inputs, specification and completion criteria, including briefing/integration.

## Review findings and independence

For explicitly selected independent or blinded review, preserve scope, evidence, actual reviewer identity and prior exposure. Use fresh context and criteria fixed before revision, reveal only permitted assigned inputs, and inspect revised evidence before the author response when required. Record observed context limits internally; a role label cannot establish independence.
